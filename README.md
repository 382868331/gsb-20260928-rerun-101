# 证据审计存储底座

这是 Go 版追加式审计日志。调用方只传入项目自身生成的事件；库不扫描、不上报也不采集用户电脑活动。

## 能力

- `Append` / `AppendBatch`：按调用方提供的来源顺序追加，每条记录包含序号、前一条哈希和当前内容哈希。
- `Seal`：封存当前完整批次，返回由调用方外部保存的 `SealSummary`。
- `VerifySealedFile`：用外部封存摘要校验任意副本，识别改写、插入、中间删除和尾部截断。
- `Open`：写入中断后只截掉物理尾部最后一条不完整帧，恢复到最后一条完整且校验通过的记录。
- `Query`：按追加/来源顺序返回记录。

## 删尾边界

文件自身只能证明现存前缀是否自洽。若攻击者从末尾完整删除一条或多条记录，被删后的文件仍可形成合法短链。因此必须把封存时的记录数和末尾哈希保存在审计文件之外；校验副本时用该摘要判断是否发生尾部截断。
