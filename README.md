# 证据审计存储底座

这是 Go 版追加式审计日志。调用方只传入项目自身生成的事件；库不扫描、不上报也不采集用户电脑活动。

## 能力

- `Append` / `AppendBatch`：按调用方提供的到达顺序写帧；每个 `source` 独立从 1 编号并维护自己的哈希链，不同来源不共享序号。
- `QuerySource`：只读取一个来源的链；`Query` 只反映文件内到达顺序，不根据事件时间或本机时间推导跨来源因果先后。
- `Seal`：封存指定来源当前完整分段，返回由调用方外部保存的 `SealSummary`，包含记录数、末尾哈希和覆盖整段的 Merkle 根。
 - `BuildRangeProof` / `VerifyRangeProof`：只向接收方披露请求序号区间、前一记录哈希和必要 Merkle 邻居；验证方可识别区间内缺号、错来源和不属于封存版本的记录。
 `VerifyRangeProofSet`：把多个独立来源各自的范围证明与各自的外部封存摘要一一配对验证；已声明来源缺证明、证明无对应摘要、重复来源都作为明确错误报告。组合验证只说明每条来源链各自完整，不把不同来源的事件时间解读成可信的全局先后。空区间（起点为 0 或终点小于起点）与越过封存段边界的区间都会被明确拒绝，落在分段中间的边界可正常验证。
- `NarrowDisclosure` / `VerifyDisclosure`：先核验父级范围证明，再从其中收窄出某一接收者获准的序号区间，生成 `Disclosure`；其中 `SealID` 与父级窗口标明该材料继承的封存依据。接收者只验证自己窗口内的记录，窗口之外的记录不可见，也不会被误报为缺失；窗口内部缺号仍会按 `missing_range` 报告。
- `MergeDisclosures`：只合并同一封存（`SealID` 相同）、同一来源、同一接收者且区间相邻或重叠的披露；重叠记录去重只计一次，重叠内容矛盾时返回 `DisclosureConflictError`，双方材料都保留、拒绝合并。来源名称相同但封存不同或接收者不同的材料一律拒绝混合。
- `DeriveReDisclosure` / `VerifyReDisclosure`：接收者在明确授权（`Authorization`）下把获准范围中的一部分转交给新接收者。授权限定来源、序号区间、可见事件类型与是否允许继续转交；再披露材料通过 `SealID` 与 `AuthorizationID` 标明继承的封存与授权。来源名称相同或持有者另有更大范围的材料，都不能扩大本次披露；窗口外记录不可见也不会被误报缺失，错误只指序号、不回放内容。
- `MergeReDisclosures`：只合并同一封存、同一授权、同一来源、同一接收者且区间相邻或重叠的再披露；不同授权下看似相同的材料拒绝合并，重叠内容矛盾时返回 `DisclosureConflictError`。
- `Registry`：登记授权补充（`NoticeGrant`）、收窄（`NoticeNarrow`）与撤回（`NoticeRevoke`）通知，按 `EffectiveAt` 时间依据计算有效范围；同一授权编号首次登记后即与原封存（`SealID`）、来源和接收方绑定，之后复用该编号但指向其他封存、来源或接收方的补充通知一律拒绝，且不改变原有范围、撤销状态或历史交付；`RecordDelivery` 按交付当时的有效范围核验并留存实际交付记录，过去的交付不因后来的收窄或撤回而消失；`RecordVerification` 保留旧时间依据下的核验记录。重复导入同一通知或同一交付不增加权限；`SaveRegistry` / `LoadRegistry` 持久化后，每次转交仍可追到当时的有效授权与实际公开范围。
- `PreviewBatch` / `AdoptBatch` / `WithdrawPending`：面向多个离线接收方成批到达的补充通知。预览只核对身份归属与时间关系，不改变当前授权，逐条给出可接纳、重复、缺少前置、身份冲突、无效或已撤销的结论；确认时只导入无争议条目，其余通知保留原文与待决原因，一条合法通知不会放行整个批次，且确认前整体校验、不会部分生效。补交前置或重选范围后再次预览会生成新的导入决定，先前决定与历史交付全部保留；相同批次重复确认不重复修改范围。维护者撤销未采用部分后，迟到的确认（包括换一批重新提交或直接 `ImportNotice`）都不能重新启用该通知。批次决定与撤销记录随 `SaveRegistry` / `LoadRegistry` 持久化，重开后可继续处理。
- `VerifySealedFile`：用外部封存摘要校验任意副本，识别改写、插入、中间删除、完整尾部删除和整段替换。
- `Open`：写入中断后只截掉物理尾部最后一条不完整帧，恢复到最后一条完整且校验通过的记录。
- `Query`：按追加/来源顺序返回记录。

## 删尾边界

文件自身只能证明现存前缀是否自洽。若攻击者从末尾完整删除一条或多条记录，被删后的文件仍可形成按来源自洽的短链；用另一个同等长度但内容不同的来源分段整段替换，也能重新算出链内哈希。因此必须把封存时的来源、记录数、末尾哈希和 Merkle 根保存在审计文件之外；校验副本或区间证明时以该外部可信摘要为准。

`SealedAt` 只是调用方的管理元数据，不参与哈希，也不能作为不同来源之间的全局先后依据。跨来源顺序只能来自事件内容或调用方明确提供、并进入哈希链的关联依据。
