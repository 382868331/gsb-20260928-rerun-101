# 证据审计存储底座

这是 Go 版追加式审计日志。调用方只传入项目自身生成的事件；库不扫描、不上报也不采集用户电脑活动。

## 能力

- `Append` / `AppendBatch`：只按调用方提供的来源追加；每个 `Event.Source` 维护从 1 开始的独立序号和哈希链。
- `Seal`：封存一个来源在当前时刻的完整版本，摘要包含来源、记录数、末尾哈希和 Merkle 根，必须由调用方外部保存。
- `BuildRangeProof` / `BuildRangeProofFromFile`：按来源和闭区间生成证明，只披露该区间内的记录及必要的 Merkle 兄弟哈希。
- `VerifyRangeProof`：验证区间记录属于外部封存摘要所确定的版本，并通过 `RangeIncompleteError` 明确列出区间内缺失序号。
- `VerifySealedFile`：用外部封存摘要校验任意副本，识别改写、整段替换、插入、中间删除、完整尾删和封存中断留下的半截帧。
- `Open`：写入中断后只截掉物理尾部最后一条不完整帧，恢复到最后一条完整且校验通过的记录。
- `Query`：按追加/来源顺序返回记录。

## 顺序与删尾边界

来源之间没有本机时钟生成的全局先后。只有事件自身携带且被哈希提交的字段可以作为应用层关联依据；存储层不会把一个来源的哈希链接到另一个来源。

文件自身只能证明现存前缀或现存来源链是否自洽。若攻击者从末尾完整删除一条或多条记录，被删后的文件仍可形成合法短链；从截断副本也无法单独重建封存版本的完整 Merkle 边界。因此必须把封存时的来源、记录数、末尾哈希和 Merkle 根保存在审计文件之外；校验副本或区间证明时用该可信摘要判断是否发生尾部截断。摘要本身不是被检查日志的一部分，不能声称单靠被检查日志证明自己没有删尾。
